---

## 1. Purpose

Extend the teleprompter player so scroll **follows the speaker in real time**: detect when the speaker is talking vs paused, **hold scroll on silence**, and **scroll faster** through script lines that are markup/meta (stage directions, datacard cues, bracketed comments) rather than spoken dialogue.

The v1 goal is a **lightweight on-time cue**, not transcript-accurate alignment: when the mic gives a useful speech signal, sync behaviour applies; **otherwise scroll defaults to normal baseline speed**.

Adaptive mode is **opt-in** in Settings, with **Auto-sync** and a **microphone control** on the player toolbar.

---

## 2. In scope / Out of scope

**In scope (initial):**

- **Live listen → pause/resume sync** with the speaker (voice-activity detection; no cloud STT)
- **Script markup parsing** — binding v1 syntax in [§4 Markup syntax](#markup-syntax-v1-binding)
- **Differential scroll speed:** normal pace for spoken lines; faster traverse for meta lines
- **Settings:** Adaptive teleprompter on/off + **Auto-sync** on/off (persisted locally; both default **off**)
- **Player mic button:** toggles sync active/inactive; when inactive → regular fixed speed
- Graceful degradation when mic permission denied or Web Audio unavailable

**Out of scope (initial):**

- Cloud STT vendors, Web Speech API dependency, or new npm speech/ML packages
- Word-level or line-level transcript alignment (“did they say the exact word?”)
- Multi-speaker diarization
- Full voice cloning / TTS playback
- Server-side audio storage or relay
- Rewriting the user's script from recognized speech
- Handoff / pairing changes

---

## 3. Domain language

| Term | Definition |
|------|------------|
| Adaptive mode | Master setting (`adaptiveEnabled`); unlocks mic UI and adaptive controller |
| Auto-sync | Setting (`adaptiveAutoSync`); when on, starting **play** auto-starts mic/listen |
| Sync active | Session state: mic listen + adaptive controller engaged (mic button **on**) |
| Spoken line | Script line intended to be read aloud at normal teleprompter pace |
| Meta line | Non-spoken markup scrolled faster; not waited on during speech pauses |
| Voice activity (VAD) | Browser-local signal: speaker likely talking vs silent (energy threshold — no transcript) |
| Baseline speed | User's `settings.speed` (0.5×–3×); default scroll rate when sync inactive or no VAD signal |
| Listen session | Mic stream open via `getUserMedia`; may exist while paused |

## 4. Behavioural spec

### Settings & UX

- **R1.** Settings exposes **Adaptive teleprompter** (on/off). Default: **off**.
- **R1b.** When adaptive is on, Settings exposes **Auto-sync** (on/off). Default: **off**. Label/copy explains: when enabled, pressing **Play** automatically starts mic sync.
- **R2.** When adaptive is **off**, player behaviour is unchanged from current `prompter-ui` (fixed-speed `useScroll` only); mic button hidden.
- **R3.** When adaptive is **on** but mic permission is not granted, show a clear non-blocking hint; fixed-speed scroll still works; mic button triggers permission request.

### Player controls

- **R4.** Player toolbar includes a **microphone button** on the **primary toolbar row** (`tp-player-toolbar__row--primary`), grouped with play and the lever strip (recommended: immediately after play). Icon-only; `aria-label` + `aria-pressed` reflect **sync active** state.
- **R5.** Mic button **toggles sync active** for the session:
  - **Sync active (mic on):** adaptive controller runs while playing — VAD may pause/resume scroll and apply meta multipliers.
  - **Sync inactive (mic off):** **regular fixed baseline speed** regardless of Auto-sync setting (explicit user override on player).
- **R6.** When **Auto-sync** is enabled in Settings and user presses **Play**, mic/listen starts and sync becomes **active** without an extra mic tap (still subject to permission).
- **R6b.** When **Auto-sync** is off, Play does not start mic; user must tap mic to activate sync (after permission).

### Speech-driven scroll (minimal-deps VAD — Q1 resolved)

- **R7.** v1 uses **browser-only** processing: `getUserMedia` + **Web Audio API** voice-activity detection (RMS/energy threshold + hangover). **No** cloud STT, **no** Web Speech API requirement, **no** mandatory third-party npm packages.
- **R8.** While **sync active** and player **playing**:
  - **Speech detected (VAD on):** scroll at **baseline speed** (user's speed slider). Optional small nudge (≤1.25×) only if implementation detects sustained lag — not required v1.
  - **Silence detected (VAD off, debounced):** **pause scroll** even if player state is "playing", until speech resumes or user pauses.
- **R9.** When sync is **inactive**, mic unavailable, or VAD signal is ambiguous/uninitialized → **baseline fixed speed** (same as today's `useScroll`). This is the explicit "otherwise defaults to normal speed" path (Q1).
- **R10.** Manual play/pause always wins: user **Pause** stops scroll immediately; listen session may continue (mic stays open) unless product disables — prefer mic stays open for quick resume.

### Markup syntax (v1, binding) {#markup-syntax-v1-binding}

**Q2 resolved:** adopt the following patterns (plain-text lines; markdown blockquotes per `markdown-render` amendment).

| Pattern | Example | Class |
|---------|---------|-------|
| Bracket tag (whole line) | `[DATACARD]`, `[CARD: title]` | `meta` |
| Parenthetical direction (whole line) | `(beat)`, `(stage direction)` | `meta` |
| C-style comment (whole line) | `/* note */` | `meta` |
| Markdown blockquote | `> direction` | `meta` |
| Plain dialogue | everything else | `spoken` |

**Note:** Whole-line `(…)` matches stage directions; spoken parentheticals (e.g. `(Hello?)`) may classify as `meta` in v1 — prefer `> blockquote` or bracket tags for dialogue in parentheses (editor hint).

**Trailing** `/* comment */` on a spoken line: v1 treats whole line as `spoken` (defer split-line to amendment).

### Markup & line classification (rules)

- **R11.** Segment script source into ordered **lines** on `\n` before classification.
- **R12.** Classify each line using the [Markup syntax](#markup-syntax-v1-binding) table → `spoken` | `meta`. No match ⇒ `spoken`.
- **R13.** Map line classifications to scroll regions:
  - **Markdown:** `blockquote` elements carry `class="tp-meta"` per `markdown-render` amendment.
  - **Plain (and all formats):** build a **line-index → pixel offset** map from `parseScriptLines` + laid-out script height (do not rely on DOM class alone for bracket/comment/paren meta lines).
- **R14.** While viewport scroll position is within a **meta** region, apply **meta scroll multiplier** (**3×** baseline effective speed — v1 default, `assumption`; tunable constant).
- **R15.** Do not wait for VAD speech on meta lines; auto-advance through meta regions when adjacent spoken content is active. Must not skip `spoken` lines.

### Integration with existing player

- **R16.** Adaptive speed adjustments are **internal multipliers** on scroll delta; the speed **slider value does not move** visually during sync (Q5 resolved).
- **R16b.** Adaptive controller composes with existing `useScroll` / viewport model; does not bypass sanitization.
- **R17.** Mirror, fullscreen, wake lock, theme, font, and padding settings unchanged.
- **R18.** `prefers-reduced-motion: reduce` disables adaptive acceleration; fixed baseline speed only.

### Brownfield fact

- **R19.** **Today** the product accepts **plain** | **markdown** only. No datacard/direction convention exists yet. v1 syntax above is **new** — requires parser module + editor hint copy.

## 5. Data model

**Client storage** — extend `tp:settings` JSON:

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `adaptiveEnabled` | `boolean` | `false` | Master toggle |
| `adaptiveAutoSync` | `boolean` | `false` | Auto-start sync on Play (Q4) |

**In-memory session state:**

| State | Notes |
|-------|-------|
| `syncActive` | Mic button / auto-sync outcome; when false → baseline speed |
| `listenActive` | `MediaStream` open |
| `vadSpeaking` | Latest VAD boolean |
| `lineClassifications` | From parser; recomputed on source change |
| `effectiveSpeed` | Feeds scroll loop |

No server tables. No audio persistence.

## 6. APIs

**v1: browser-only (Q1 resolved — minimal dependencies)**

| Surface | Purpose |
|---------|---------|
| `navigator.mediaDevices.getUserMedia({ audio: true })` | Mic capture |
| `AudioContext` / `AnalyserNode` | Local VAD (energy threshold) |

**Explicitly not used in v1:** cloud STT HTTP, Web Speech API, pairing-api changes, new backend routes.

**Internal modules (proposed):**

- `frontend/src/prompter/adaptive/parseScriptLines.ts`
- `frontend/src/prompter/adaptive/useVoiceActivity.ts`
- `frontend/src/prompter/adaptive/useAdaptiveScroll.ts`
- `frontend/src/prompter/adaptive/types.ts`

## 7. Invariants

- **I1.** Raw audio never leaves the device; never sent to analytics, pairing API, or third parties.
- **I2.** Adaptive off ⇒ zero `getUserMedia` calls.
- **I3.** Script source unchanged by adaptive mode.
- **I4.** XSS rules unchanged; meta classification is pre-render string ops + sanctioned HTML class from `markdown-render` amendment.

## 8. Error model

| Condition | UX |
|-----------|-----|
| Mic permission denied | Alert + fixed-speed scroll; mic shows denied state |
| Web Audio unavailable | Disable sync; settings note on unsupported browser |
| Audio context suspended (iOS) | Resume on user gesture (play/mic tap) |
| Empty script | No errors; sync no-ops |
| Long script | Classify off main thread if n > 8k lines (`assumption` threshold) |

## 9. Observability

| Event | When |
|-------|------|
| `adaptive.enabled` | Setting on |
| `adaptive.auto_sync.enabled` | Auto-sync on |
| `adaptive.sync.start` / `.stop` | Sync active toggled |
| `adaptive.vad.error` | Audio pipeline failure (code only) |
| `adaptive.fallback_fixed_speed` | Sync off or no VAD → baseline |

No transcript or audio payloads in events.

## 10. Security and privacy

- Mic access requires user gesture (Play with auto-sync, or mic tap).
- Device-local VAD only (Q1); aligns with ADR 004 device-local content.
- Settings privacy copy: "Audio is processed on this device only; nothing is uploaded."
- **Review gate:** standard SPEC review (not cloud high-risk); mic permission UX still requires a11y check.
