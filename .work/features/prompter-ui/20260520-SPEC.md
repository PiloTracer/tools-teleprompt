## 1. Purpose

Browser-based teleprompter: capture script (plain/markdown), configure display, scroll during presentation. Supports same-device workflow, PWA offline shell, and client-side QR handoff initiation. Does not implement server relay (see `pairing-api` SPEC).

---

## 2. In scope / Out of scope

**In scope:**

- Script editor (paste, type, file upload `.txt`/`.md`)
- Teleprompter player (speed, play/pause, font, mirror, theme, fullscreen, wake lock)
- Local persistence (`localStorage` + IndexedDB fallback)
- PWA manifest + service worker (offline app shell + cached assets)
- QR handoff UI (generate/consume) for scripts ≤ threshold
- Responsive layout (phone, tablet, desktop)

**Out of scope:**

- User accounts, cloud sync
- Server pairing logic (API SPEC)
- Markdown parse/sanitize implementation detail (`markdown-render` SPEC)

---

## 3. Domain language

| Term | Definition |
|------|------------|
| Script | User-authored plain or markdown text |
| Player | Fullscreen scrolling teleprompter view |
| Handoff | Transfer script to another device (QR or relay) |
| Settings | Speed, font size, theme, mirror — persisted locally |

---

## 4. Behavioural spec

- **R1.** User can enter or upload a script; accepted extensions: `.txt`, `.md`; max size per config (default 256 KB).
- **R2.** Script and `format` (`plain` | `markdown`) persist in browser storage and reload on return visit.
- **R3.** Player supports play/pause auto-scroll, speed slider (0.5×–3× baseline), font size adjustment, light/dark theme.
- **R4.** Player supports fullscreen and optional horizontal mirror for camera setups.
- **R5.** Where supported, Screen Wake Lock activates during active playback.
- **R6.** Markdown scripts render via `markdown-render` pipeline only; never bypass sanitization.
- **R7.** Plain scripts render as escaped pre-wrapped text (no HTML interpretation).
- **R8.** PWA: after first successful load, app shell and static assets load offline; prompter works offline when script exists locally.
- **R9.** For scripts ≤ QR threshold (~8 KB compressed), UI offers QR handoff encoding payload in URL **fragment** (no server POST).
- **R10.** For larger scripts, UI offers relay handoff (calls `pairing-api`) with URL + OTP display.
- **R11.** Direct open on mobile (no handoff route) skips OTP and pairing screens.
- **R12.** Keyboard shortcuts on desktop: space = play/pause, +/- = speed, `f` = fullscreen (document in UI help).

---

## 5. Data model

**Client storage keys (localStorage unless quota → IndexedDB):**

| Key | Content |
|-----|---------|
| `tp:script:source` | UTF-8 text |
| `tp:script:format` | `plain` \| `markdown` |
| `tp:settings` | JSON `{ speed, fontSize, theme, mirror }` |

No server-side tables.

---

## 6. APIs

Consumes `pairing-api` HTTP endpoints only (see pairing SPEC). No public API exposed by frontend.

---

## 7. Invariants

- **I1.** Script source never sent to analytics or third parties.
- **I2.** QR fragment payload never logged to console in production builds.

---

## 8. Error model

| Condition | UX |
|-----------|------|
| File too large | Block with message showing limit |
| Storage quota exceeded | Prompt to clear or shorten script |
| Offline + no cached shell | Browser default offline message |

---

## 9. Observability

Optional client metrics (no script content): `handoff.qr.generated`, `handoff.mode.relay`, `player.started`.

---

## 10. Security and privacy

- Data classification: script = sensitive user content; device-local only after load.
- CSP compliance for inline styles (teleprompter theming).
- See `markdown-render` SPEC for XSS controls.
